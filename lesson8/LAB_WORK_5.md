## Задание 1. Класс «Табличный набор данных»

**Цель:** инкапсулировать `DataFrame` и базовые сведения о нём в одном объекте.

1. Создайте класс `TabularDataset`.
2. **Конструктор** принимает либо `pd.DataFrame`, либо данные, из которых можно собрать `DataFrame` (например, `dict` столбцов или список записей с общими ключами). Внутри сохраните копию: `df.copy()` (или эквивалентно безопасное копирование).
3. Реализуйте:
   - свойство **`data`** — возвращает **копию** внутреннего `DataFrame`;
   - **`shape`** — кортеж `(число строк, число столбцов)`;
   - **`column_names`** — список имён столбцов;
   - **`head_info(self, n: int = 5) -> str`** — строка с результатом `head(n)` в виде текста (например, `str(self._df.head(n))`);
   - **`numeric_summary(self) -> pd.DataFrame`** — результат `describe()` только для **числовых** столбцов (если числовых нет — пустой `DataFrame` с ожидаемой структурой или осмысленное поведение по согласованию с преподавателем — зафиксируйте в комментарии).

**Демонстрация:** создайте объект от небольшой таблицы с колонками `name`, `age`, `score`; выведите `shape`, первые строки и числовое описание.

## Задание 2. Класс «Репозиторий CSV»

**Цель:** отделить чтение/запись файла и проверку схемы данных от остальной логики.

1. Создайте класс `CsvRepository`.
2. **Конструктор** принимает `path: str | pathlib.Path` — путь к CSV-файлу и **обязательный** список имён столбцов `required_columns: list[str]`, которые должны присутствовать после загрузки.
3. Реализуйте методы:
   - **`load(self) -> TabularDataset`** — читает CSV через `pd.read_csv`, проверяет наличие всех `required_columns`; при отсутствии любого столбца — `ValueError` с понятным сообщением; возвращает `TabularDataset` с загруженными данными;
   - **`save(self, dataset: TabularDataset) -> None`** — записывает `dataset.data` в тот же путь через `to_csv` (формат на усмотрение: по умолчанию `index=False`).

**Демонстрация:** создайте временный CSV в папке с работой (или используйте подготовленный файл), загрузите через репозиторий, выведите `shape` набора; затем измените копию данных в памяти (через новый `TabularDataset` или методы следующих заданий) и сохраните обратно.

## Задание 3. Наследование: преобразования `DataFrame`

**Цель:** полиморфизм — разные классы, один интерфейс для шага обработки таблицы.

1. Создайте абстрактный базовый класс `DataFrameTransform` (`abc.ABC`) с абстрактным методом  
   `apply(self, df: pd.DataFrame) -> pd.DataFrame`  
   который возвращает **новый** `DataFrame` и **не изменяет** переданный `df` (работайте с копией внутри).
2. Реализуйте **не менее двух** подклассов, например:
   - `FilterByScoreTransform` — в конструкторе порог `min_score: float`; в `apply` оставляет только строки, где столбец `score >= min_score` (имя столбца можно задать параметром конструктора, по умолчанию `"score"`);
   - `AddPassedColumnTransform` — добавляет булев столбец `passed`: `True`, если `score >= 70`, иначе `False`.
3. Общую проверку «вход — `pd.DataFrame`» и наличие нужных столбцов можно вынести в приватный метод базового класса, чтобы не дублировать код в каждом подклассе.

**Демонстрация:** на одной и той же таблице последовательно примените два разных преобразования и выведите фрагмент результата.

## Задание 4. Композиция: конвейер преобразований таблицы

**Цель:** объект «имеет» несколько стратегий и применяет их по порядку.

Реализуйте класс `PandasTransformPipeline`:

- конструктор принимает последовательность объектов `DataFrameTransform` (например, `*transforms` или список);
- **`run(self, df: pd.DataFrame) -> pd.DataFrame`** — применяет преобразования **по порядку**; исходный `df` не мутирует;
- **`describe(self) -> str`** — строка со списком имён классов преобразований в порядке применения (например, через `type(t).__name__`).

**Демонстрация:** соберите pipeline из преобразований задания 3 (например, сначала фильтр по баллу, затем добавление `passed`), прогоните через него `DataFrame` с 5–7 строками.

## Задание 7. Наследование: стратегии обработки пропусков

**Цель:** разные способы заполнения/удаления пропусков как подклассы одного контракта.

   `apply(self, df: pd.DataFrame) -> pd.DataFrame`  
   (возвращает новый `DataFrame`, исходный не меняет).
2. Реализуйте **два** подкласса, например:
   - `FillNumericMeanStrategy` — для указанного списка числовых столбцов заполняет `NaN` средним по столбцу (столбцы без чисел — по согласованию: пропуск или `ValueError` с сообщением);

3. Создайте класс **`MissingValueProcessor`**, который в конструкторе принимает `MissingValueStrategy` и имеет метод `process(self, df: pd.DataFrame) -> pd.DataFrame`, делегируя стратегии.

**Демонстрация:** один `DataFrame` с пропусками в `score`; обработайте его двумя разными стратегиями и выведите размеры таблиц до/после.
